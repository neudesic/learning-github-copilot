# 🚀 Getting Started with GitHub Copilot Edit

---

### 📝 Overview

GitHub Copilot Edit is one of three modes of GitHub Copilot (Ask, Edit, Agent), designed to help you make precise, targeted modifications to your code using natural language instructions.

## What Is GitHub Copilot Edit?

GitHub Copilot Edit is a powerful code modification tool that enables you to apply precise changes to specific files or code sections using natural language instructions. Unlike Ask mode, which provides guidance without changing your code, Edit mode actually rewrites your code based on your instructions—but always shows you exactly what will change before applying any modifications.

What makes Edit mode particularly valuable is its surgical precision. You can target specific methods, classes, or code blocks and ask Copilot to refactor them, add error handling, optimize performance, or implement new features. The tool understands context from your existing codebase and maintains consistency with your coding patterns and style.

Edit mode is perfect for brownfield applications where you need to make controlled changes without affecting the rest of your system. It's also excellent for applying consistent patterns across multiple files or implementing targeted improvements in performance-critical sections.

- **Precise Modifications**: Target specific code sections for controlled changes

- **Surgical Precision**: Perfect for brownfield applications and targeted improvements

## How It Works – Step by Step

Here's how to use GitHub Copilot Edit effectively:

1. **Open Copilot Edit Mode**
   - **Method 1:** Use the keyboard shortcut `Ctrl+I` (Windows/Linux) or `Cmd+I` (Mac) and selct Edit option
   - **Method 2:** Open Command Palette (`Ctrl+Shift+P`) and search for "Copilot: Edit"

   ![Github Copilot Edit Access](./images/copilot-edit.png 'GitHub Copilot Edit Access')

2. **Select the Code You Want to Modify**
   - Highlight the specific block of code you want to change.
   - This could be a method, class, code block, or even multiple files.
   - 💡 Tip: Be precise with your selection - Edit mode works best with well-defined boundaries.
   - **Example Selection**: If you want to refactor a method, select just that method's code block.
    - **Example Selection**: If you want to changes across multiple files, hold `Ctrl` (Windows/Linux) or `Cmd` (Mac) while selecting the files in the file explorer.
    - **Example Selection**: If you want to modify a class, select the entire file or just the class definition.

   **Why selection matters:**  
   Your selection defines the scope of changes. Copilot Edit will only modify the code within your selection, ensuring other parts of your codebase remain untouched.

3. **Provide Your Instructions**
   - Type your modification request in natural language
   - Be specific about what you want to achieve
   - Examples of good instructions:
     - "Add error handling with try-catch blocks"
     - "Refactor this to use async/await pattern"
     - "Add input validation for all parameters"
     - "Optimize this method for better performance"
     - "Convert this to use dependency injection"

   ![Github Copilot Edit Instructions](images/copilot-edit-instructions.png 'GitHub Copilot Edit Instructions')

4. **Review the Proposed Changes**
   - Copilot will show you a diff view highlighting exactly what will change
   - Green lines show additions, red lines show deletions
   - Review the changes carefully to ensure they meet your requirements
   - The original code remains unchanged until you accept

   ![Github Copilot Edit Diff](images/copilot-edit-diff.png 'GitHub Copilot Edit Diff')

5. **Accept or Reject the Changes**
   - **Accept**: Click "Accept" or press `Ctrl+Enter` to apply the changes
   - **Reject**: Click "Reject" or press `Escape` to cancel without any modifications
   - **Iterate**: You can modify your instructions and try again if needed

   💡 **Pro Tip**: You can also use the "Accept" and "Reject" buttons for individual hunks of changes if you only want to apply part of the suggested modifications.

## Advanced Edit Mode Techniques

### 1. **Multi-File Editing**

    - Select code across multiple files (hold `Ctrl` while selecting)
    - Edit mode can apply consistent changes across your selection
    - Perfect for applying the same pattern to related files

### 2. **Iterative Refinement**

    - Start with a broad instruction, then refine in follow-up edits
    - Example: First "add error handling", then "improve the error messages"
    - Each iteration builds on the previous changes

### 3. **Context-Aware Instructions**

    - Reference other parts of your codebase in instructions
    - "Use the same pattern as in UserService.cs"
    - "Follow the error handling approach from the BaseController"

### 4. **Combining with Custom Instructions**

    - Set up custom instructions for your team's coding standards in `copilot-instructions.md` file
    - Edit mode will automatically apply your style preferences
    - Ensures consistency across all modifications

## Best Practices for Effective Editing

### ✅ **Do's:**

1. **Be Specific with Instructions**
   - ✅ "Add null checks and throw ArgumentNullException with descriptive messages"
   - ❌ "Make this safer"

2. **Select Appropriate Scope**
   - Choose the right amount of code - not too little, not too much
   - Include related methods if they need to change together

3. **Review Changes Carefully**
   - Always examine the diff before accepting
   - Ensure the changes align with your intentions

4. **Use Iterative Improvements**
   - Make one type of change at a time
   - Build on previous modifications gradually

5. **Leverage Context**
   - Reference existing patterns in your codebase
   - Mention specific frameworks or libraries you're using

### ❌ **Don'ts:**

1. **Don't Use Vague Instructions**
   - ❌ "Fix this code"
   - ❌ "Make it better"

2. **Don't Select Too Much at Once**
   - Avoid selecting entire large files unless necessary
   - Focus on logical units of code

3. **Don't Accept Without Review**
   - Always review the proposed changes
   - Understand what's being modified before accepting

4. **Don't Forget to Test**
   - Test your changes after applying them
   - Ensure functionality remains intact

## When to Use Edit Mode vs. Other Modes

### **Use Edit Mode When:**

- You need to modify existing code
- You want precise, targeted changes
- You're working in brownfield applications
- You need to apply consistent patterns
- You want to refactor specific methods or classes
- You need to add features to existing implementations

### **Use Ask Mode When:**

- You want to understand code without changing it
- You need explanations or guidance
- You're learning new concepts
- You want to explore alternative approaches

### **Use Agent Mode When:**

- You need changes across multiple files
- You want Copilot to work autonomously
- You're building new features from scratch
- You need architectural changes

### 🚨 Common Mistakes to Avoid

1. **Selecting Inappropriate Scope**: Choose the right amount of code for your changes
2. **Vague Instructions**: Be specific about what you want to achieve
3. **Not Reviewing Diffs**: Always examine proposed changes before accepting
4. **Trying to Change Too Much**: Focus on one type of modification at a time
5. **Ignoring Context**: Consider how changes affect the rest of your codebase
6. **Accepting Without Testing**: Always test your changes after applying them
7. **Not Using Iterative Approach**: Break complex changes into smaller steps

### 💡 Pro Tips

1. **Use Custom Instructions**: Set up team coding standards for consistent results
2. **Reference Existing Patterns**: Mention other parts of your codebase as examples
3. **Start Small**: Begin with simple changes and build up to complex modifications
4. **Combine with Ask Mode**: Use Ask mode to understand before using Edit mode to modify
5. **Save Before Editing**: Always save your work before making major changes
6. **Use Version Control**: Commit frequently when making iterative improvements
